# Backend v2 — خطة التنفيذ ذات المراحل الثلاث

**النطاق:** باك إند جديد ومنفصل بـNode.js/JavaScript، تحليلات، لوحة رسوم، مطابقة مهارات، وبوابة ML اختيارية لتصنيف عائلات الوظائف. لا يستورد هذا العمل الباك إند أو التحليلات أو النماذج القديمة ولا يعدّلها.

**حدود البيانات:** قاعدة SQLite المصدر أُعيد بناؤها من أجزاء SQLite الـ11 المصرح بها فقط في مجلد Drive `NADA`. مجلد Drive `JOP_MARKETING_2 - Cleaned Data (Audit 2026-10-28)` هو مرجع بيانات التنظيف والمنشأ؛ تمت مطابقة أعداد الملفات السبعة وأسمائها في حقل `source_file` مع الملخص المعتمد (المجموع `775,155`). بصمة CSV المذكورة في manifest تخص gzip CSV، وليست بصمة SQLite. لم تُستخدم أو تُفحص بقية ملفات NADA، ولم يُعدّ تاريخ تعديل Drive تاريخ نشر/جمع للإعلانات.

## المرحلة 1 — مصدر البيانات وبنية Node.js المعزولة

1. إعادة تركيب SQLite فقط من الأجزاء الـ11 المعتمدة وبالترتيب الرقمي، ثم اختبار gzip وSQLite والمخطط.
2. إنشاء تطبيق `backend_v2/` مستقل: إعدادات، adapter للقراءة فقط، فحص مخطط، HTTP/errors/request IDs، ومدخل Vercel.
3. إضافة قاعدة fixture صغيرة واختبارات وحدة وتكامل.
4. **بوابة المرحلة:** فحص الصياغة والاختبارات و`quick_check` ومطابقة أعداد مصادر الملفات قبل الانتقال للمرحلة التالية.

**النتيجة:** نجحت إعادة تركيب gzip من 11 جزءًا (`986,484,511` بايت؛ SHA-256 `a8a9d46b63a9f923dfe07a074ed07f16bc0a6c0643974abb8692a0f713f9efab`)؛ `gzip -t` و`PRAGMA quick_check` كلاهما `ok`. أعداد جدول المصدر: 775,155 إعلانًا/صف تدقيق، 4,026,953 رابط مهارة، 1,498 مهارة. تطابقت أسماء ملفات المصدر السبعة وأعدادها مع ملخص Drive. لا يُكتب إلى القاعدة المصدر.

## المرحلة 2 — التحليلات والرواتب والرسوم ولوحة العرض

1. تثبيت هوية الدور على `title_key` وتوفير البحث والتقرير الكامل.
2. تنفيذ إجمالي الإعلانات، الطلب حسب الدور والدولة، ونسبتين واضحتَي المقام لكل توزيع.
3. تنفيذ تكرار المهارات والتقنيات المشتركة، والرواتب السنوية، وأنماط العمل، والأسواق العربية/الدولية.
4. استخدام أعمدة الرواتب السنوية الجديدة USD/EGP/SAR وحالاتها؛ عدم استعمال العمود الخام القديم الفارغ أو دمج العملات.
5. بناء payloads قابلة للرسم ولوحة HTML عربية متجاوبة، مع إبقاء مواقع unknown منفصلة وعدم وصف `not_remote_explicit` بأنه حضور مؤكد.
6. **بوابة المرحلة:** اختبارات بمقامات ونتائج fixture يدوية، وفحص استعلام تقرير فعلي، وإعادة جميع اختبارات المرحلة الأولى.

**النتيجة:** جميع عائلات التحليل المطلوبة موجودة في API/اللوحة. تقرير `Data Engineer` الفعلي يعيد 56,524 إعلانًا، مهارات ورواتب ونسبًا لكل دولة. لوحة البيانات الفعلية ولّدت snapshot صغيرًا للاستخدام البارد على Vercel. تعرض النسب مقاماتها، والرواتب السنوية مفصولة حسب العملة، وأنماط العمل توضح دلالة `not_remote_explicit`.

## المرحلة 3 — المطابقة وML والتغليف والتوثيق النهائي

1. تنفيذ مطابقة مهارات exact/alias قابلة للتفسير تعرض المهارات المتطابقة والناقصة، وتغطية مهارات المستخدم والإعلان، وفلاتر اختيارية؛ لا تعرض احتمال توظيف أو حكمًا شاملًا على الملاءمة.
2. تدقيق تسميات عائلات الوظائف بوصفه تقرير provenance لا بوابة. تدريب مصنف Node.js مستقل على `role_family` باستخدام TF-IDF + Multinomial Naive Bayes، وتقسيم مجموعات النص المتطابقة، وإظهار per-class precision/recall/F1 وMacro-F1 ومصفوفة الالتباس مع توضيح أنها تقيس الاتفاق مع التسميات المخزنة.
3. بناء إسقاط نشر صغير ومضغوط من قاعدة NADA المصرح بها، والتحقق من الجداول والروابط والمهارات والرواتب وحالاتها، واختبار فك ضغط gzip للقراءة فقط.
4. إعداد `vercel.json` وإدراج الأصول المطلوبة، مع توثيق أن artifact قاعدة النشر ignored ويلزم توفيره لحزمة Vercel؛ لا يُدّعى اكتمال نشر لم يُنفذ.
5. إنشاء `API_REFERENCE.md`, `TESTING_NOTEBOOK.md`, `BUG_REPORTS.md`, و`ANALYTICS_REPORT.md`، ثم إعادة جميع بوابات الاختبار.

**النتيجة:** المطابقة قابلة للتفسير وتعيد `hiringProbability:false`. دُرّب موديل `role_family` على 775,155 إعلانًا و16 فئة؛ split الاختبار المحجوز أعاد accuracy 94.1457% وmacro-F1 76.6955% وweighted-F1 94.1527%. تدقيق `NO_GO` بقي تحذير provenance لا بوابة inference؛ المقاييس تقيس الاتفاق مع التسميات المشتقة ولا تثبت حقيقة أرضية مستقلة. حُفظ الموديل المضغوط والتقييم، ونجح فحص status/predict الحقيقي. قاعدة الإسقاط: 775,155 صفًا، 4,026,953 رابطًا، و1,498 مهارة؛ `quick_check=ok`، تطابقت أعداد الجداول وجميع أعمدة الرواتب السنوية التسعة وحالات الرواتب. حجم SQLite الخام `279,310,336` بايت، وgzip `79,477,402` بايت؛ أُضيف فك الضغط إلى مجلد مؤقت لأن الملف الخام يتجاوز ميزانية الدالة. تم فحص التطبيق فعليًا عبر وضع `VERCEL=1`، لكن لم يُنفذ نشر إلى Vercel.
