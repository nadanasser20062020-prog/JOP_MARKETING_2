# هيكل المستودع المقترح

الهيكل التالي يفصل التحليل عن قاعدة البيانات والنماذج والموقع. الموجود الآن هو هيكل توثيق وتخطيط؛ لا يعني أن ملفات تنفيذ التطبيق قد كُتبت. تُضاف الملفات التنفيذية بعد إنجاز تدقيق الداتا واختيار التقنيات.

- **`docs/`** — وثائق النطاق والخطة والبيانات والتحليل وML والواجهة وطريقة العمل.
- **`data/`** — README وقواميس بيانات أو عينات صغيرة مسموح بمشاركتها فقط. ملفات Drive الخام أو النسخ المعالجة الكبيرة تبقى خارج Git.
- **`database/`** — ERD، تعريف الجداول، تعليمات Neon، وقرارات التحميل.
- **`analysis/`** — استعلامات SQL ودفاتر التحليل الاستكشافي والرسوم والتقرير.
- **`ml/`** — إعداد بيانات النمذجة والتجارب وقياس الأداء وتفسير النماذج.
- **`backend/`** — طبقة الخدمة التي تتعامل مع قاعدة البيانات وتوفر نتائج آمنة للواجهة.
- **`frontend/`** — صفحات الموقع، البحث والمرشحات والرسوم وتجربة العربية والإنجليزية.
- **`tests/`** — اختبارات تنظيف البيانات والعلاقات والاستعلامات والنماذج والواجهات.
- **`.github/`** — قوالب المهام ومراجعة التغييرات.

## قواعد التنظيم

- لا تضعوا كل العمل في Notebook واحد؛ قسّموا الدفاتر حسب سؤال التحليل واجعلوا النتائج قابلة لإعادة التشغيل.
- لا تضعوا مفاتيح Neon أو بيانات المستخدمين أو الملفات الخام في Git.
- اجعلوا SQL التحليلي منفصلًا عن SQL إنشاء الجداول عند بدء التنفيذ.
- لا تضعوا رسومات أو أرقامًا نهائية في الواجهة قبل توثيق مصدرها وتعريف مقياسها.
- قبل اختيار أطر الواجهة والخلفية، راجعوا ما يعرفه الفريق ومتطلبات الاستضافة؛ الخطة لا تفرض Stack لم يُتفق عليه.
