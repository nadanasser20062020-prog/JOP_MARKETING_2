# خطة الموقع وتدفق البيانات

## الغرض

تحويل نتائج قاعدة البيانات والتحليلات إلى تجربة بسيطة للمهندسين: استكشاف سوق الوظائف، ثم فهم الوظيفة أو المهارات التي تناسبهم وما الذي يمكن تعلمه بعد ذلك.

## تدفق النظام المقترح

1. بيانات الإعلانات تُنظف وتُحمّل إلى PostgreSQL/Neon.
2. التحليلات والنماذج تعمل على بيانات موثقة وتُنتج مؤشرات أو توصيات.
3. طبقة خلفية آمنة تقرأ البيانات وتنفذ البحث والتصفية والاستعلامات المطلوبة.
4. الواجهة تعرض النتائج والرسوم والتفاصيل للمستخدم.

لا تتصل واجهة المتصفح بقاعدة Neon مباشرة، ولا تُضمّن فيها بيانات اعتماد قاعدة البيانات. اختيار framework ولغة التنفيذ يُحسم مع الفريق قبل البدء بالتنفيذ؛ لا يفرض هذا المخطط تقنية غير متفق عليها.

## الصفحات وتدفق الاستخدام

### 1. الصفحة الرئيسية

- ملخص حجم العينة والأسواق والفترة المتاحة.
- أبرز الوظائف والمهارات ومؤشرات سوق العمل المتاحة.
- روابط مباشرة إلى مستكشف الوظائف ومقارنة الأسواق ومطابقة المهارات.

### 2. مستكشف الوظائف

- البحث والتصفية بحسب الحقول التي تدعمها الداتا.
- نتائج موجزة توضح المسمى والشركة والموقع ونمط العمل والمهارات أو الراتب إذا توفرت.
- حالات واضحة للتحميل، وعدم وجود نتائج، وعدم وجود قيمة.

### 3. تفاصيل وظيفة

- عرض المعلومات التي جُمعت عن الإعلان، والمهارات، والتاريخ، ومصدر الإعلان.
- تمييز الراتب المكتوب في الإعلان عن أي توقع نموذجي.
- رابط إلى صفحة الإعلان الأصلية إن كان الرابط صالحًا.

### 4. تحليل السوق ومقارنة الدول

- رسوم للوظائف والمهارات وأنماط العمل والرواتب المتاحة.
- اختيار سوقين أو أكثر للمقارنة.
- رسوم زمنية فقط عندما تكون التواريخ كافية وموثوقة.
- إظهار حجم العينة وتعريف كل مقياس.

### 5. مستكشف المهارات

- عرض المهارات الأكثر طلبًا بحسب وظيفة أو سوق.
- عرض المهارات المرتبطة أو المتكررة معًا.
- الانتقال من مهارة إلى الوظائف التي تظهر فيها ومصادر تعلمها.

### 6. مطابقة المهارات ومصادر التعلم

- إدخال مهارات المستخدم واختياريًا تفضيلات البلد أو نمط العمل.
- عرض الوظائف/المسارات الأقرب، وشرح التطابق والمهارات الناقصة.
- إرفاق مصادر تعلم مجانية مرتبطة بكل مهارة ناقصة، مع حالة التحقق من المجانية.

### 7. المنهجية

- شرح مصادر الداتا وتاريخها، والتنظيف والتعريفات وطريقة التحليل والنماذج وحدود الاستنتاج.

## العربية والإنجليزية

- واجهة باللغة العربية والإنجليزية، بما في ذلك ترجمة التنقل والعناوين ورسائل الحالة.
- دعم اتجاه RTL للعربية وLTR للإنجليزية من دون قلب الروابط والأرقام.
- الحفاظ على مسمى الوظيفة الأصلي، مع استخدام مسمى موحّد للمقارنة عند الحاجة.

## مهام التنفيذ المقترحة

1. تثبيت تدفق المستخدم والحقول المطلوبة بعد Data Audit.
2. رسم تخطيطي للشاشات ومراجعة الفريق قبل البرمجة.
3. تجهيز استعلامات القراءة والتجميع في الخلفية.
4. تنفيذ مستكشف الوظائف وتفاصيل الإعلان.
5. تنفيذ لوحة السوق والمقارنة ومستكشف المهارات.
6. دمج المطابقة ومصادر التعلم.
7. إضافة اللغتين وحالات عدم وجود البيانات والموبايل.
8. اختبار الأرقام والروابط والسرية وإمكانية الاستخدام.

## معايير قبول عامة

- كل رقم في الواجهة يمكن تتبعه إلى استعلام أو نتيجة تحليل موثقة.
- المرشحات لا تعرض خيارات غير موجودة في الداتا، وتعمل مع قيم مفقودة.
- كل وظيفة معروضة مرتبطة بمصدرها إن كان المصدر موجودًا.
- الواجهة تعرض نقص البيانات بوضوح ولا تستبدله بقيم مخترعة.
- مخرجات المطابقة قابلة للتفسير ولا تدعي ضمان التوظيف.
- التطبيق لا يحتوي على أسرار اتصال ولا يتيح وصولًا غير مقصود إلى قاعدة البيانات.
- لا تشمل النسخة الحالية حفظ الوظائف أو البحث أو التنبيهات.
